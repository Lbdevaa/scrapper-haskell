# scrapper-haskell

Выгрузка каталога vprok.ru на Haskell. Порт API-части проекта
`puppeteer-vprok` (`part2.js`) без браузера: запрос идёт обычным HTTP-клиентом,
куки берутся с главной страницы.

Что умеет:

1. **История цен** — каждый прогон дописывает строки в CSV (`--csv`).
2. **Наличие** — команда `stock` показывает, чего нет в продаже.
3. **Топ скидок** — `--order discount --top N`.
4. **Diff двух прогонов** — что подешевело, подорожало, появилось, исчезло.

## Сборка

```
cabal build
```

Нужен GHC 9.2+ и cabal (ставятся через [ghcup](https://www.haskell.org/ghcup/)).

## Использование

Категорию можно задать полной ссылкой, путём каталога или голым
идентификатором — всё это одно и то же:

```
cabal run scrapper -- fetch https://www.vprok.ru/catalog/7382/pomidory-i-ovoschnye-nabory
cabal run scrapper -- fetch /catalog/7382/pomidory-i-ovoschnye-nabory
cabal run scrapper -- fetch 7382
```

Прогон с отчётом и накоплением истории:

```
cabal run scrapper -- fetch 7382 --limit 60 --report report.txt --csv history.csv
```

Топ-20 скидок из уже сохранённого снапшота:

```
cabal run scrapper -- report snapshots/7382/20260827-101500.json --order discount --top 20
```

Чего нет в наличии:

```
cabal run scrapper -- stock snapshots/7382/20260827-101500.json
```

Сравнение двух прогонов:

```
cabal run scrapper -- diff snapshots/7382/20260826-101500.json snapshots/7382/20260827-101500.json
```

## Как устроено

| Модуль | Ответственность |
| --- | --- |
| `Vprok.Types` | Товар, разбор JSON, производные величины (скидка, наличие) |
| `Vprok.Api` | Разбор ссылки на категорию, куки, запрос к API |
| `Vprok.Snapshot` | Сохранение и чтение сырых ответов |
| `Vprok.Report` | Текстовые отчёты и сортировки |
| `Vprok.Diff` | Сравнение двух снапшотов |
| `Vprok.Csv` | История цен |

Сырой ответ API сохраняется целиком в `snapshots/<категория>/<время>.json`.
Отчёт из снапшота собирается всегда, обратно — нет, поэтому снапшот является
основным артефактом, а `report.txt` — производным.

## Отличия от JS-версии

- Не нужен браузер: `puppeteer` был нужен только чтобы `fetch` ушёл с куками
  сайта, это делает и обычный HTTP-клиент.
- Исправлено поле «Акционная цена»: в `part2.js` туда попадала обычная цена,
  из-за чего «Цена» и «Акционная цена» всегда совпадали. Теперь акционная цена
  заполняется только при реальной скидке.
- Исправлен двойной слэш в ссылке на товар (`https://www.vprok.ru//product/...`).
- Числа из API разбираются и когда приходят строкой, и когда числом, и когда
  `null` — один странный товар больше не роняет весь прогон.
